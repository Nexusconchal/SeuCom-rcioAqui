API de parceiros

Versão 1 • Uma chave por loja • Valores em centavos de real (BRL)

Crie uma chave em Painel → Integrações. A chave completa aparece uma vez. Use apenas no servidor do parceiro; nunca em JavaScript público, URLs ou logs. Revogar a chave bloqueia imediatamente o acesso.

Autenticação e permissões

Authorization: Bearer SUA_CHAVE
Content-Type: application/json

orders:read permite consultar a loja e as entregas prontas ou em andamento. deliveries:write permite vincular e atualizar entregas. A chave não pode alterar produtos, confirmar pagamentos ou acessar outras lojas. O custo da corrida pode ser informado ao vincular a entrega. Limite: 120 requisições por minuto por chave. HTTPS obrigatório em produção.

1. Testar a conexão

curl 'https://seucomercio-aqui.onrender.com/api/v1/store' \
  -H 'Authorization: Bearer SUA_CHAVE'

2. Buscar entregas

GET /api/v1/deliveries?after=0

{
  "deliveries": [{
    "id": 123, "number": 1001, "status": "ready",
    "customer": "Cliente", "phone": "19999999999",
    "address": "Rua Exemplo, 10, Centro, Conchal - SP",
    "mode": "delivery", "total": 3500, "delivery_fee": 500,
    "paid": true, "payment": "pix", "notes": "",
    "pickup": {"name": "Loja", "address": "Rua Origem, 20", "phone": "19999999999"},
    "items": [{"name": "Lanche", "quantity": 1, "notes": "Sem cebola"}]
  }],
  "next_after": null
}

Até 100 registros por página, ordenados pelo ID. Continue com next_after enquanto ele não for nulo. Em cada ciclo de consulta, comece novamente em zero: pedidos antigos podem ficar prontos depois. Consulta sugerida a cada 30–60 segundos. O parceiro deve persistir os vínculos e deduplicar pelo ID da loja e do pedido; dados em memória não bastam.

3. Vincular uma entrega

POST /api/v1/deliveries/123/claim

{
  "provider": "motoja",
  "external_id": "ID_DA_ENTREGA_NO_MOTOJA",
  "delivery_cost": 650
}

Vincula somente pedido de entrega no status ready. O custo é opcional, em centavos. Repita os mesmos dados para recuperar o vínculo (200 com duplicate: true); outro código, parceiro ou chave retorna 409. Um vínculo por pedido, e um código externo por parceiro e loja. Vincular não muda o status do pedido nem confirma pagamento.

4. Informar saída e conclusão

POST /api/v1/deliveries/123/events

{"event_id": "motoja-entrega123-saida-v1", "status": "delivering"}

POST /api/v1/deliveries/123/events

{"event_id": "motoja-entrega123-conclusao-v1", "status": "completed"}

A mesma chave que vinculou a entrega deve enviar os eventos. A ordem permitida é ready → delivering → completed. Use um event_id estável por evento e persista-o antes do envio. Repetição idêntica é aceita sem duplicar efeitos; reutilização com dados diferentes retorna 409. O parceiro não pode cancelar pedidos, reabrir pedidos ou marcar pagamento.

Erros e tentativas

CódigoConduta
400Corrigir os dados enviados.
401 / 403Verificar chave, permissões, loja e vínculo. Não repetir continuamente.
404Pedido inexistente ou pertencente a outra loja.
409Reconciliar estado, vínculo e identificador antes de repetir.
429 / 5xx / timeoutRepetir com espera progressiva, usando os mesmos identificadores (ex.: 5, 15, 60 segundos). O serviço gratuito pode levar cerca de um minuto para iniciar.

Conector MotoJá

Esta API já define o contrato que o MotoJá deve consumir. O conector do MotoJá precisa guardar a chave no servidor, associá-la à empresa correta, buscar pedidos prontos, criar ou recuperar a entrega de forma idempotente, vincular o código externo e enviar os eventos. A criação de uma chave aqui não instala nem ativa esse conector no outro sistema.

Antes de ativar despacho real, validar vínculo da empresa, preço e saldo no MotoJá, idempotência na criação da corrida, rejeições, cancelamento pela loja, repetição de eventos e reconciliação após falhas. Não usar o valor do pedido como preço da corrida. Não incluir a chave em links ou parâmetros de navegação.
